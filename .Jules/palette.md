## 2024-03-24 - Screen Reader Compatibility with Visual Focus

**Learning:** When making hover-only CSS animations (like image overlays) accessible via `:focus-visible`, simply adding `tabIndex={0}` to the container is sufficient to trigger the CSS state. Adding `role="button"` without keyboard event handlers is an anti-pattern for screen readers, and adding `aria-hidden="true"` to hide the overlay from screen readers completely prevents them from reading legitimate captions/titles inside the overlay. Screen readers already interact well with semantic HTML (like `img` with `alt` text and adjacent text nodes) without needing to simulate interactive widget roles on containers that aren't truly interactive buttons.
**Action:** When fixing visual keyboard focus (`:focus-visible`) on structural elements (like cards or image wrappers) that do not have `onClick`/`onKeyDown` handlers, do NOT add `role="button"`. Ensure `tabIndex={0}` is used purely to allow keyboard focus for visual state, and let screen readers read the native semantic HTML inside.
